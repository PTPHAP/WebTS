# 1.1.2：协议时序与图片兼容性复核

本次审查针对1.1.1之后的增量：TeamSpeak确认/保活时序、图片与头像限制、管理界面的参数校验及发布包。账号、Olm、对象存储加密和音频模型没有更换；本记录不代替这些模块各自的既有验收。

## 发现与处理

| 问题 | 触发与影响 | 修复与验证 |
| --- | --- | --- |
| P2：命令RTT包含发送前等待 | 命令已入队但尚未发送，例如等待连接处理；统计会把本地排队误算为对端往返，还影响重传估计 | 使用成功发送记录的时间；加密UDP回环测试先复现失败，再验证排队不进入RTT、真实对端等待仍进入RTT |
| P2：新保活包未立即尝试发送 | 保活截止时间与统计事件错开，下一次轮询前存在额外等待；可能抬高同机RTT | 同一轮询内刷新发送队列，socket暂不可写仍保留原队列；记录成功发送时间，不增加轮询频率或忙等待 |
| 兼容性：原头像文件上限过小 | 原生客户端可显示的头像超过128KiB，网页在下载前拒绝 | 默认原文件上限提高至2MiB，管理员最多4MiB；大于旧上限的真实PNG解码和安全缩图回归 |

定位：`patches/raw-audio.patch`中`tsproto/src/connection.rs`、`tsproto/src/resend.rs`；`server/tests/protocol_rtt.rs`；`server/src/settings.rs`、`server/src/avatar.rs`、`web/src/image-limits.ts`及其测试。

## 安全边界

- 确认包仍须经过原协议处理；不从网页传入的时间戳计算RTT。重发包继续排除出RTT采样，原始入队时间继续用于超时保护，未取消超时或重传。
- 不修改密钥、认证、UDP来源检查、DTLS/SRTP套件或强制TS语音加密；不新增公网接口、端口、第三方服务或依赖。
- 图片下载先检查声明长度，流读取和时间限制保留；每连接头像任务最多两个，昂贵解码继续受已有工作池限制。
- 原生头像仍限制4096px边长、800万像素及32MiB解码资源；只接受PNG/JPEG/GIF/WebP，重新编码后输出头像不超过原站点保存上限。不是把原图直接交给网页执行。
- 频道图保持最多4096px边长、80MiB解码资源和192KiB输出上限；缓存、读取频率、SSRF防护和频道可见性检查保留。图片数量和原文件大小可提高，不增加单次解码并发。
- 后台和浏览器对新增范围采用相同校验；已有站点配置不因升级自动覆盖。修改现有站点时应只调整图片字段，保留服务器、SMTP、对象存储、节点与自定义政策。

## 发布检查与实际使用

发布仍要求同一提交的依赖审查、Rust、前端、多浏览器、Linux/Docker和Windows检查全部通过，运行包仅使用该提交CI产物。公开包不能包含本地配置、数据库、身份、密钥、进度记录和临时诊断。

代码回归证明上述时序和限制边界；实际声音延迟还包括采集、降噪、网络与播放缓冲。不得将RTT变小当作声学延迟已经同等变小，或将合成回环当作某台部署服务器已验收。使用同机节点时，协议修复必须更新实际TS机器上的节点；仅更新主站不会替换远程节点程序。

本机Windows检查：Rust工作区221项通过、5项依赖指定环境的测试按原规则跳过；前端256项通过并完成构建；安装/打包脚本25项检查、其中2项平台相关跳过。协议回归修复前两项失败、修复后三项通过。干净上游源码规范化行尾后应用公开补丁，两个时序源文件与实测版本一致。Linux与Windows发布产物仍须完成同提交CI，不以这些本机结果替代。

本次增量复核未发现需要阻断发布且尚未处理的P0/P1；如对应提交的检查失败，仍阻断安装包发布。安全判断基于上述检查和已记录范围，不使用版本名称代替检查结果。
