# 备份与恢复验收

[文档中心](README.md) · [部署](DEPLOYMENT.md) · [Linux 安装](INSTALL.md) · [Windows](WINDOWS.md)

> 开发补充，尚未随正式安装包发布。本文的合成数据验收验证账号、托管 TS 身份和站点设置；不代表真实 TS 通话、对象存储或端到端私信的完整灾备已经通过。

## 必须保留什么

| 内容 | 用途 | 丢失的后果 |
| --- | --- | --- |
| 一致性 SQLite 备份 | 账号、身份密文、设置和业务记录 | 无法恢复相应账号或元数据 |
| 原部署主密钥 | 解密托管身份和站点加密设置 | 改网站密码或重发邮件也不能代替 |
| 配置及外部凭据 | 监听、SMTP、TURN、S3 等 | 相应功能无法连接；凭据轮换后需重新核对 |
| 同版本程序和前端、版本号与摘要 | 重现兼容运行环境 | 新旧数据库或运行库可能不兼容 |

数据库与密钥必须成对可恢复，但长期备份应分别加密保存并控制访问。默认备份目录可能同时包含两者，目录权限不能替代备份加密。备份含个人数据和凭据，禁止上传 GitHub、公开对象桶或提交工单附件。

Linux 中文管理工具的 `webts backup` 使用 SQLite 在线备份接口生成一致性快照，不是直接复制正在写入的主数据库文件。Windows 的 `webts.cmd backup` 要求先停服，复制默认目录中的 `data`、`secrets` 和配置。两种目录结构不同：Linux 快照数据库位于备份根目录的 `web-ts.db`，Windows 位于 `data/web-ts.db`。手动修改过数据库/密钥路径时，必须另外核对实际文件，不能只备份默认目录。

恢复不能只靠“文件数量正确”判断。至少应完成以下流程。

## 恢复流程

1. 记录故障时间、程序版本和备份时间，保留当前故障现场及原数据。恢复到全新目录，先用相同版本验证，不覆盖正在使用的目录，不把旧快照直接写回仍在运行的 SQLite。
2. 准备隔离运行环境，阻止连接原 SMTP、TeamSpeak、对象存储和其他外部服务。只修改监听地址不足以隔离后台任务；可使用无外网容器或明确的防火墙规则。当前生产实例与恢复副本不能共享同一份可写数据库。
3. 放回一致性数据库、对应的**原主密钥**和配置。若手工复制 SQLite，应先正常停止来源实例并完整保留必要 WAL；不要单独复制仍在写入的 `.db`。`init-key` 不是恢复步骤，不能生成替代密钥。
4. 检查恢复副本文件权限、SQLite `quick_check` 和 `foreign_key_check`。错误主密钥、缺失主密钥或未知迁移不得忽略继续上线。
5. 在恢复副本**首次对用户开放前**撤销全部旧登录会话和旧邮箱令牌。备份中的会话可能在故障前已经退出或撤销，恢复旧数据库会使这些记录重新出现。不要仅依赖用户上线后手动退出。
6. 使用新的登录验证原账号、站点名称与配置、原 TS 身份 UID；本人重新输入密码后导出并在隔离环境检查身份。确认其他账号不能导出该身份，测试账号找回及会话撤销。真实 SMTP、TS 和 TURN 连通另在受控环境验收。
7. 核对临时对象/私信过期状态、外部凭据、版本兼容和数据缺口，完成管理员确认后再切换正式服务。避免原实例与恢复实例同时运行后台清理或邮件任务。回退程序时不得为了方便用旧数据库覆盖恢复后新产生的用户数据。

第 5 步可在**停服的恢复副本**上使用 SQLite 工具执行以下事务，执行前先确认打开的是恢复副本的数据库。它保留账号和身份，旧设备需要重新登录，未完成验证/找回邮件需要重发：

```sql
PRAGMA foreign_keys = ON;
BEGIN IMMEDIATE;
DELETE FROM sessions;
DELETE FROM email_tokens;
COMMIT;
PRAGMA quick_check;
PRAGMA foreign_key_check;
```

现有 `session_details` 随会话外键级联删除。若工具关闭外键或发现完整性错误，先停止处理并检查；不能跳过错误宣称恢复成功。该事务本身不重置私信设备身份或清除对象存储内容。

### 快照之后的安全变更

撤销旧会话仍不足以处理整个恢复时间差。备份之后修改的密码、账号封禁/解封、管理员角色、好友屏蔽及隐私偏好，可能随旧快照回到旧状态。正式开放前应依据受控记录逐项核对，优先恢复安全限制；不能默认快照中的旧管理员权限或较宽松隐私设置仍获授权。

无法可靠重建这些变更时，应保持恢复实例不对用户开放，完成受影响账号的密码重置、权限/封禁和隐私状态核对，再决定启用范围。本工具不自动合并故障之后的安全变更，也不代表这些故障场景已经验收。

## 运行合成数据验收

在包含 `scripts` 的项目/运行包根目录，使用可信的本机网关二进制运行。Python 仅用标准库，不发送真实邮件、不连接 TS，不读当前部署的 `data`、`secrets` 或 `config.local.toml`。全部数据生成于独立 `.cache/recovery-smoke-*` 目录，结束时关闭测试进程并清理；无法启动或断言失败即不通过。

Linux：

```sh
python3 scripts/tests/recovery-smoke.py --binary ./web-ts
```

Windows：

```powershell
python scripts/tests/recovery-smoke.py --binary .\web-ts.exe
```

源码开发环境也可传入实际构建出的程序路径。固定的测试密码和 Argon2id 哈希只用于临时合成账号，不是站点管理员凭据。脚本不会初始化现有站点，也不是生产一键恢复工具。

该检查会实际启动原生网关，通过本机 HTTP 登录、创建身份；调用安装管理工具的一致性备份，在有 WAL 的情况下生成快照；验证快照不包含之后写入的身份；恢复到全新目录并执行上面的会话撤销步骤。随后验证原账号可重新登录、原 UID 保留、原身份可解密导出并去重导入、其他账号被拒绝，错误/缺失密钥被拒绝，旧密钥不被覆盖。报告只打印检查摘要，不打印密码、私钥或 Cookie。

后续 Linux/Windows CI 将对当次构建的程序执行该检查。接入检查并不等于某次 CI 已通过；应查看对应提交的实际结果。本机 Windows 验证也不能代替 Linux/Docker、真实故障机及外部供应商故障演练。

## 临时消息与 E2EE 的边界

- 多存储开发版须同时恢复每个存储配置的原编号、凭据和对象索引；切换默认写入不会迁移旧对象。不能只恢复当前默认桶的参数；失去原配置会导致对应内容无法读取或清理。详见[多存储与回退](OBJECT-STORAGE.md)。
- 对象存储中的内容不在 SQLite 文件内。已过期、阅后删除或已被桶生命周期清理的对象，不能靠恢复数据库重新出现；不得延长原消息保留期限来掩盖缺失。
- 普通临时私信的密文、元数据和部署密钥需要一致核对；不能只检查对象数量或数据库条目就认定消息可读。
- Olm 设备私钥和棘轮状态由用户设备管理，站点数据库备份不是用户的设备密钥备份。设备丢失仍按端到端私信自己的加密备份/身份重置流程处理，不能承诺恢复旧消息。
- 数据库回到旧时间点还可能回退设备登记、预密钥、消息收据或租约。没有完成对应独立验收前，不得宣称 E2EE 灾备就绪；发现状态不一致应停止相关发送并走明确恢复流程，不能悄悄切换成服务器可解密模式。
