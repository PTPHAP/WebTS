# 1.1.3 维护复核与验证边界

本次维护聚焦语音时间轴、乱序包恢复、本地音频处理控制、安装入口及发布资源。没有变更账号权限模型、身份加密、好友加密协议或存储权限；隐私政策的数据处理范围保持一致。

## 已复核的改动

- 降噪 worklet 显式启动消息队列，使过滤模式确认、打字消音及销毁消息实际执行。增强模式保留 GTCRN 与 RNNoise 两段过滤；未采用削弱键盘噪声抑制的识别直通方案。
- 增强模型故障时先静音，基础过滤确认后才恢复；确认超时暂停麦克风。模式切换清空旧缓冲，销毁取消计时器并解绑回调，避免残留音频和重复故障处理。
- 每个发言者使用固定大小的接收位图，仅恢复同一语音段、相同帧时长的合法乱序包；重复、过旧及跨段数据被拒绝。补帧不回拨源时钟，保留语音结束标记、空闲恢复及整数时间戳回绕处理。
- Windows 运行包检查新 worklet 文件名；测试从实际加载器读取两个资源版本。浏览器 CI 使用同提交产物中的音频及加密资源，不通过跳过测试解决资源缺失。

## 可复核证据

隔离 Windows 测试运行 30 分钟：50 个收听连接，每个预分配 50 条音轨，10 个发言者合计 500 条单向 AES-256-GCM 音轨。发送 44,966,080 包、收到 44,965,383 包；逐音轨送达门槛均超过 99%。回环转发平均约 2.36ms，P95 上界桶 5ms，最大约 107.6ms；采样内存峰值约 175MiB。这些数值不含 TeamSpeak、浏览器解码或真实麦克风，不是 Linux 参考机器容量或嘴到耳延迟。

同音频上下文、同输入的默认增强模式对照中，键盘样本的残留均方根幅度与原链一致，人声输出能量接近。真实浏览器检查覆盖处理器故障后的静音、跨线程确认、恢复输出、播放链复用、收听静音及直达控制回退；缺少音频能力的环境明确跳过，不能视为真实手机通过。

授权独立 TS3 的协议客户端联调通过双向 Opus、加密普通语音及耳语、句首补发、结束发言、聊天、双向头像、权限拒绝、会话撤销，以及自定义地址去重与热撤权。它使用协议客户端，不代替官方桌面客户端听感对照。需要额外描述权限的 AFK 测试未满足测试身份前提，不计为通过，也未因此放宽 TS 权限。

## 发布约束与后续验收

运行包发布要求同一提交的依赖公告、Rust、Docker、Windows 和浏览器五项 CI 全部成功，并核对安装与恢复证据、包清单、源码版本及校验值；结果可在[构建记录](https://github.com/PTPHAP/WebTS/actions/workflows/check.yml)查看。公开包仅包含许可允许的源码、运行文件及文档，不包含本地进度、配置、账号、私钥、诊断原始音频或缓存。

本次复核不是独立第三方审计。真实手机外放、游戏负载、网络切换、四方向原生同期延迟及 Linux 参考机器容量继续按[发布门槛](RELEASE-GATES.md)验收；不以版本号、面板 RTT 或本机合成测试替代这些结果。主站与同机节点分开更新，保留原配置、密钥及回退备份，具体见[节点教程](NODE-INSTALL.md)。
