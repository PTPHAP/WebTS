# 语音质量与异常恢复

在“语音设备设置 → 语音诊断”查看以下数据。未得到有效统计时显示“—”，不使用猜测值补齐。

| 指标 | 含义与范围 |
| --- | --- |
| 当前网页构建 | 本页实际加载的入口文件标识，用于双方核对是否为同一修订；不是服务器最新版本，也不是安全认证 |
| 音频上下文、实际处理方案 | 当前播放/处理上下文和正在运行的处理链；暂停、系统中断、处理失败与未启动分别显示，不把配置选择当作实际运行 |
| 接收轨道 / 输出元素 / 已暂停输出 | 当前接收链的数量快照；不含静音解码辅助附件，不等于频道人数或可听声音数量。已暂停输出与主动静音不同，刚连入时为零可以正常 |
| 回声消除 · 请求 / 设备报告 | 是否请求开启，以及采集设备实际报告的开关；未报告不推断为已关闭，报告开启也不代表实际声学效果通过 |
| 浏览器 ↔ 网关 RTT | 当前选中 WebRTC 候选链路的往返时间；直连与 TURN 分别显示 |
| 网关 ↔ TeamSpeak RTT | 原生协议库报告的往返时间，独立于浏览器链路 |
| 近期接收丢包、播放缓冲 | 相同音频流计数器的增量，窗口最多10秒；新连接、流计数重置和长时间恢复前台后重新采样 |
| 音频补偿采样与事件 | 浏览器为丢失或迟到音频合成的采样和连续补偿事件；不直接等同可听断音，也不据此修改麦克风处理 |
| 网关转发队列 | 该连接最近一个网关统计周期的入队等待时间，平均值及10ms分桶的P95上界；仅计算进入队列后的等待，不包含网络、AI或满队列的入队前丢弃 |
| 累计缓冲与丢包 | 当前浏览器连接的累计数据；网络恢复后仍可能保留旧影响 |

网关统计通常每2秒发布，实际窗口显示在界面；任务被阻塞时窗口可能更长。浏览器一次只保留一个未完成统计请求，3秒超时后清除旧数据显示不可用，迟到结果不再发布。统计失败不会中断通话，也不会无限追加未完成请求。

RTT、AI算法延时、音频设备、编码和播放缓冲属于不同环节，不能把这些数值简单相加当作完整说话到听见的延时。AI模型加载耗时也不等同运行延时。实际人声开口、音色、游戏负载及端到端P95需要另外进行同步声学测量。音频补偿字段依据 [W3C WebRTC Statistics](https://www.w3.org/TR/webrtc-stats/)。

## 网络和设备故障

### 移动端外放回声（开发补充，尚未随正式安装包发布）

回声消除由麦克风采集端的浏览器/系统提供，本地 AI 降噪不能替代它。语音诊断分别检查请求开启与设备实际报告；“设备未报告”不代表已经关闭，“已启用”也不保证任何音量或房间都能消除回声。

开发版脱敏报告格式为 `webts-diagnostic-v4`：保留原有字段，增加 `frontendBundle` 与 `runtime`。构建只接受本页同源、无查询参数的标准入口路径；未知构建为 `null`。运行状态使用固定枚举，数量只接受非负安全整数，未知数据为 `null`。不导出原始设备设置、轨道编号、账号、地址、设备名称、密钥、聊天或录音；不自动上传、保存或新增诊断轮询。下载前请自行预览，再决定是否分享。正式旧包可能仍导出旧格式，排查时先核对加载构建。该标识用于排障，不用于验证代码真实性。

收听音量、成员音量及发言时回声减弱统一通过 Web Audio 增益节点控制，静音另有媒体元素静音保护。辅助解码附件只绑定独立的、已禁用的远端音轨副本，再加元素静音/零音量，原始音轨仅进入正常处理链；不再用“音量读回为零”作为不会重复播放的保证。这考虑了 [Apple 记录的 iOS 媒体音量限制](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/Using_HTML5_Audio_Video/Device-SpecificConsiderations/Device-SpecificConsiderations.html)。依据 [W3C 媒体流规范](https://www.w3.org/TR/mediacapture-streams/#dom-mediastreamtrack-enabled)，禁用音轨给消费者的是静音；副本在播放链销毁时停止，不改变借用的原始轨道。

真实本机 WebRTC 检查会故意将辅助元素取消静音、音量调满，确认副本采样仍为零、正常处理链有声，并覆盖双向收发、重新协商、收听静音与恢复。这是针对重复播放旁路的验证，不是对所有移动内核或实际手机声学效果的保证。浏览器差异仍需按实际平台验收；直接删除远端解码附件可能造成无声，不应作为未经验证的兼容修复。

重新协商可能再次通知同一远端音轨，接收端会复用现有播放链，避免叠音和旧播放器失去回收入口；音轨结束后释放播放链，后续新轨道正常建立。依据 [W3C 远端音轨处理流程](https://www.w3.org/TR/webrtc/#processing-remote-mediastreamtracks)，并通过本机真实 WebRTC 更改流关联后的重新协商验证。此项不能替代两部外放手机的声学验收。

两部手机复测时，双方都须加载同一修订版。先在不同房间以适中音量外放，依次单方说话、同时说话、静音/恢复、热切换降噪和切换页面；记录哪一方听见自己的回声及双方报告的回声状态。再比较一方戴耳机的情况。不要仅凭模拟 iPhone 的桌面浏览器结果宣称实机通过；同一房间多设备外放形成的交叉声路也需要单独区分。

WebRTC进入短暂断开状态后等待10秒，期间恢复则保留连接；持续断开或明确失败时回收旧连接，再按已有1–30秒退避自动重试。手动断开、会话失效及权限撤销仍停止相应操作。重连尝试恢复断线前的频道，目标不存在、身份变化或权限不足时不会绕过服务器限制，必要时提示输入频道密码。

麦克风暂停、采样失败和设备切换优先恢复采集链，保留服务器连接与收听；降噪热切换保留当前处理链，失败时不会静默降级为发送原始麦克风。浏览器休眠、系统网络变化和移动系统后台限制仍需要实机验证。

转发队列最多8包，并拒绝等待超过200ms的旧包；自由发言开口缓冲与转发使用同一到达时间，不额外延长旧包的保留期。负载满时可能产生音频缺口，这是避免积压旧声音的取舍，不降低加密下限。主动关闭明确撤销加密就绪状态、取消接收任务并关闭RTC传输。

## 隔离长时测试

开发环境安装固定Rust依赖后，可单独运行：

```sh
cargo test --package web-ts --test rtc_soak --locked -- --ignored --nocapture
```

默认持续30分钟，50组本机真实UDP/DTLS-SRTP连接、其中10组双向合成Opus静音。它只检查传输、套件、计数和关闭流程；不连接生产TeamSpeak，不替代真人听验、降噪处理、TS网关全链路或Linux参考机器容量验收。测试默认被常规快速测试跳过；可通过`WEBTS_SOAK_SECONDS`指定10–7200秒，短时结果不能作为30分钟验收。输出仅含数值摘要，原始音频和网络地址不写入报告。

Windows不允许链接器覆盖运行中的测试程序；运行长时测试期间可执行其他检查，完整重编译应在长时测试结束后进行。
