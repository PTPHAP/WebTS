# 架构与数据流

## 选定结构

浏览器 React/TypeScript → HTTPS/WSS账号与信令 + WebRTC加密音频 → 单Rust/Tokio/Axum网关 → 每网页一条真实TS UDP连接 → 站长配置的TS3/TS6服务端。

SQLite保存用户、密码哈希、身份密文、登录会话、验证/恢复令牌。SMTP发送验证及找回邮件。音频热路径不访问数据库，也不经过SMTP或密码哈希工作队列。

## 身份数据流

导入或网页创建 → 验证私钥并计算UID → AES-256-GCM加密并绑定用户/身份标识 → 数据库保存密文。连接选择身份ID → 后端按登录用户查询归属 → 临时解密 → 真实TS握手。

导出要求重新验证网站密码，只下载当前账户的所选身份。网站账号恢复不改变TS UID，也不授予TS权限。

## 接口边界

认证：注册、验证、重新发送验证邮件、登录、当前用户、退出、退出全部设备、找回和重置。

身份：列表、创建、导入、名称/默认设置、删除、导出。请求不以用户传来的ownerID作为授权来源。

连接：站长配置列表/默认项，管理员开启后可用自定义公网地址，选择identityID建立会话、状态事件、频道/聊天/管理命令、断开和WebRTC协商。解析后以实际地址限制同UID重复连接。所有TS命令使用本人连接，不使用站长Query账户代操作。

管理：GET/POST `/api/admin/settings` 仅限已验证管理员会话，保存要求当前密码。角色通过主机端CLI授予，不允许普通注册自提权。邮件和连接设置整体加密保存到SQLite，通过进程内共享快照立即更新；基础部署参数仍保留文件配置。普通用户只看到服务器名称/ID、默认项和自定义开关，不能获取SMTP参数或授权码。

## 固定依赖

tsclientlib提交与raw-audio补丁记录在THIRD_PARTY_NOTICES.md和patches/。Cargo.lock固定实际依赖。raw-audio只开放原始音频包，不增加音频转码。


## 社区与账号偏好

好友关系和普通/E2EE模式选择按账号保存，普通模式按有效会话授权，端到端消息额外要求设备租约与本机密钥。账号非秘密偏好通过GET/PATCH `/api/preferences`合并，固定字段且检查当前账号；设备、频道密码和E2EE安全码信任不跨设备同步。

连接注册表从当前原生状态保存最小服务器/频道信息，好友接口验证共享开关、关系、会话和目标配置。POST `/api/friends/{peer}/join`返回当前可用连接引用和频道；真正连接与移动仍进入现有身份归属、公网目标和TS权限检查。在线状态是网关近期活动，无法追踪原生客户端在其他服务器的登录。
