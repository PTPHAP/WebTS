## B. 资产与信任边界

- 新入口：`/api/auth/username`及`/api/auth/qr/{start,poll,inspect,approve,claim,cancel}`；固定JSON字段和2KiB请求体上限，沿用同源检查、入口限流、工作队列及安全Cookie。
- 新表：`login_names`、`quick_logins`；`session_details`增加`public_device`。别名不是权限标识。旧会话默认为原个人设备行为，原邮箱验证/找回保留。
- 待扫码凭据和已登录Cookie是不同资产。手机授权凭据不能领取电脑登录；数据库只存凭据摘要。电脑领取后为独立短期会话，不是手机会话的永久子登录。
- 公共设备可使用本人托管TS身份；不能管理身份或网站后台。真实TS权限仍由服务器判断。站点本来就能解密托管身份，扫码没有改变该信任边界。
- 不增加外部扫码服务、CDN或依赖。Olm、语音、S3正文加密协议未改动，不把本次登录检查等同于密码学审计。

## C. 不变量核对

| 不变量 | 检查方式与证据范围 |
| --- | --- |
| 两端必须主动确认，且账号不能随Cookie变化 | 手机确认和电脑领取都带显示的账号编号，服务端提交前比较；账号切换失败用例及真实HTTP验证 |
| 二维码不是登录Cookie | 独立256位随机确认/领取凭据、摘要入库、120秒期限、单次事务；错误凭据、取消、过期和重放测试 |
| 撤权及时生效 | 领取事务重验授权会话、封禁、验证状态和协议；已领取电脑可由安全中心单独撤销 |
| 公共限制由服务器决定 | 四小时上限、公共＋记住登录拒绝、后台/身份管理/设备租约/模式切换/再次授权拒绝；不信任前端开关 |
| 公共模式不新增设备私钥 | 不自动加载本机身份/信任记录；备用入口禁用且敏感函数提前返回，普通与端到端聊天不自动降级 |
| 队列和请求有界 | 最多1000个短期请求、有效请求独立轮询限额、IP粗限额、原全局入口和阻塞工作池；未据此认证容量 |
| 新旧数据兼容 | 事务迁移及旧邮箱/个人会话回归；启动后失败禁止自动旧程序覆盖新安全语义 |
| 秘密不进入公开源代码 | 公开文件路径、已知本地凭据和令牌格式检查；本地配置、数据库、缓存与进度记录排除 |

## E. 原因、条件与修正代价

**QL-01：** 需要手机已查看请求，之后另一个标签页切换账号，再点击旧页面确认。仅在响应后比较账号来不及阻止服务端副作用。已将期望账号放入手机确认和电脑领取，事务写入前核对；错误账号不消耗正确领取机会。实际保留失败复现及修复后通过结果。新增字段只属于本次新接口，前后端应同时部署；旧候选页面需刷新。

**QL-02：** 需要公共用户从普通好友聊天的小齿轮进入设备设置；虽然最终服务器登记受限，但创建/导入函数可能更早写本地身份。已限制全部相关按钮、渲染分支和函数入口，并在收发资格中排除公共设备。新增浏览器入口回归与函数提前停止测试。代价是公共设备不能操作E2EE备份，需在个人设备使用；既有E2EE不会因此降级。

**QL-03：** 站点账号原本为管理员，或请求方另持有有效旧设备租约时，单纯隐藏UI不足以改变后端权限。公共会话的管理员视图明确为false，社区管理另行拒绝，设备租约检查先拒绝公共会话；覆盖正确密码/原管理员身份/已有租约等情况。TS本人的权限不受冒充站点角色影响，也不额外剥夺TS权限。

**QL-04：** 新程序已开始运行并写入数据，随后就绪检查失败，旧更新器原本会自动重新启动旧程序。旧程序不认识公共会话的权限限制或新内容版本，存在错误解释风险。现改为停止本实例、保留候选程序/当前数据库/原镜像；受限备份目录记录前后源码位置。合成命令回归证实原行为并核对修正。代价是故障时需维护介入、可用性下降。旧版已经运行中的更新脚本不会追溯获得修正，首次跨版本升级须维护窗口与兼容验收；不允许盲目删库或恢复旧快照。

**QL-05：** 无确定线程调度的线上复现，不把推断包装成攻击成绩。协议读锁现持有至授权/领取事务完成，沿用runtime→数据库锁序；测试确认检查期间无法换协议、退出后释放锁。代价是管理保存可能短暂等待，事务中没有网络请求。

**QL-06：** 比较发现格式/导入顺序差异，没有据此声称存在新的协议漏洞。公开补丁与实际文件同步后，从固定上游提交重新应用，115份公开vendor源文件按规范化行尾比较一致，嵌套gitlink固定且干净。根仓库不依赖未上传的子模块提交。

**QL-07：** 保存旧默认政策摘要时，Windows CRLF与实际匹配函数的LF规范化不一致；此前默认政策可能不会自动加入新处理说明。用真实历史默认文本保留LF/CRLF升级失败用例，改为规范化摘要后两种行尾均更新；原有自定义政策保留测试继续执行。只识别完全一致的历史默认文本，自定义政策仍由运营者自行更新，不扩大自动覆盖范围。

本报告面向源码候选。公开源码不等于已经制作并验收所有运行包，也不等于已更新生产网站。正式Linux、Docker、Windows和源码包必须按[发布门槛](RELEASE-GATES.md)及同提交CI结果逐项验收，不能把旧版附件改名为新版。

如发现未解决P0/P1应阻断正式发布。CI失败不能被本机通过替代。真实手机/品牌浏览器、生产HTTPS扫码、旧版升级、TS6、独立Linux容量、TURN长连接及E2EE独立集成审计仍须分别验证；相应实验边界保持。
