# 发布范围与验收门槛

版本号不代表“没有漏洞”。当前正式核心范围为账号、TS3 网关和网页工作区；TS6、移动语音和好友端到端私信继续保留实验标识。具体证据和局限见 [支持范围](SUPPORT.md)。

## 安装包交付

正式公开安装包前须实际通过：锁定依赖检查、Rust 安全测试与代码检查、前端回归和构建、Linux 与 Docker 启动、完整源码独立容器构建、Windows 原生初始化和启动检查。每个正式版本生成源码、Linux、Docker 和 Windows 四类包与校验文件；标签和源码版本必须一致。任一任务失败不自动附加运行包。

安装包只能包含程序、固定网页资源、公开模板、文档和许可，不含账号、数据库、私钥、实际邮箱配置、内部进度和临时文件。校验文件用于检查传输完整性，不能替代对仓库维护者与发布流程的信任。

## 好友端到端私信转正式

首个正式范围可以保持“一次一台设备”，不必先实现多设备历史同步。转正式前需要以下可复核结果：

| 门槛 | 必须覆盖 |
| --- | --- |
| 收发正确性 | 双用户、Chrome/Edge/Firefox、真实手机；离线送达、乱序、重复、断网重试 |
| 密钥生命周期 | 自动设备密钥、固定身份、备份导出/恢复、设备接管、账号撤销、同账号多个标签页 |
| 模式隔离 | 明确选择服务器可解密模式、旧消息分离、模式切换中上传失败；E2EE 不自动降级 |
| 状态持久化 | 解密与棘轮提交失败、掉电/浏览器退出恢复、加密缓存删除，不因重试重复推进状态 |
| 阅后即焚 | 已读首次计时、重复确认不延期、服务器保留上限优先、离线与多浏览器显示一致 |
| 对象存储 | 实际供应商上传/读回/删除、限流/超时/权限拒绝、清理积压、生命周期和恢复演练 |
| 安全复核 | 独立审计 WebTS 的 Olm 接入、信任固定、密钥管理及消息上下文认证 |

使用经过审计的上游组件不等于应用集成已经通过独立审计。Olm 与 Signal 是不同协议，不自创算法补充，也不宣称截图、录屏或被控制的终端绝对可防。

## 后续顺序

近期语音质量与举报处理包含快速回归、账号/角色撤销、并发处理冲突、纯文本防注入、窄屏界面、RTC真实加密往返及端口释放检查；50组连接/10组合成Opus的本机长时测试默认单独运行。它们不替代真实麦克风、游戏负载、VPN/Wi-Fi切换、移动系统后台和独立Linux参考容量验收。新增举报数据库表时先备份，回退旧程序不能整库覆盖升级期间的新材料或消息；旧程序不提供举报入口，先停止相关写入再评估回退，优先向前修复。

CI 的 `private-browser` 使用当前提交的 WASM，在 Chromium、Firefox、WebKit 和移动 WebKit 模拟视口中运行真实 WebCrypto、IndexedDB 及 Web Locks 检查：自动密钥重载、两个隔离设备双向/乱序/重放、事务中止后的重置重试、备份恢复及多标签页锁；另使用模拟账号接口检查完整页面反复切换无残留，以及隔离播放器实例保持连续。可从项目根目录运行：

```bash
# 先按 FRIENDS.md 构建固定 WASM；浏览器只用于隔离合成数据
cd web
npm ci
npx playwright install --with-deps chromium firefox webkit
npm run test:browser
```

这些检查不连接生产账号或S3，不代替真实供应商故障、品牌浏览器/物理手机、浏览器进程崩溃或独立密码学审计。移动模拟不等于真实手机验收。正式运行包发布还要求本提交 `private-browser` 成功。

先完善安装/更新/回退与故障恢复，再完成上述 E2EE 验收；之后逐步推进多设备方案、社区治理和容量扩展。容量、语音端到端 P95 和长期稳定性必须在独立环境测量，不能从容器限制或理论设计推断已经达标。正式开放规模应与实际验收结果匹配。
