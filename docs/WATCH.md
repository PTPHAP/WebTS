# 联合观赛中心

联合观赛页面位于 `/watch`。它与现有 TeamSpeak 语音连接共用页面外壳，切换到观赛页不会主动断开语音；直播视频由平台播放器或官方直播间提供，WebTS 不下载、录制或转发视频。

此功能为尚未打包发布的源码更新，现有 1.0.6 安装包不包含。默认关闭，需管理员配置活动；一个活动支持主舞台和最多 7 个副舞台。

## 免费能力与平台边界

| 平台 | 链接识别 | 公开标题、简介及封面 | 站内播放 |
| --- | --- | --- | --- |
| 哔哩哔哩直播 | `https://live.bilibili.com/房间号` | 公开网页元信息，受平台响应限制 | 管理员确认允许嵌入后，使用官方活动播放器 |
| 虎牙 | `https://www.huya.com/房间号或别名` | 公开网页元信息，受平台响应限制 | 本轮使用官方直播间跳转 |
| 斗鱼 | `https://www.douyu.com/房间号` | 公开网页元信息，受平台响应限制 | 本轮使用官方直播间跳转 |
| YouTube | 视频链接、`/live/视频ID`、youtu.be | 公开网页元信息 | 官方隐私增强播放器 |
| Twitch | 频道链接 | 公开网页元信息 | 官方播放器，绑定本站域名；窄屏使用官方链接 |
| 其他平台 | 公网 HTTPS 网页链接 | 若页面公开且含元信息，可尝试读取 | 官方跳转，不允许任意 iframe 或 HTML |

直播页面可能采用动态渲染、登录限制或访问控制，仅读取网页不保证取得所有信息。读取失败时可手动填标题、介绍及上传裁剪封面。本站不会使用用户 Cookie 抓取内容或绕过平台限制。B站房间号校验只读取其播放器所用的公开 `room_init` 房间信息，转换短号为实际房间号；不读取直播流、弹幕或比赛数据。

没有确认可免费供本站使用的 B站/虎牙完整 CS2 比赛数据接口。直播标题、弹幕及视频播放不等于队伍比分、经济或选手统计。当前提供手动赛况与签名数据接口，不内置付费订阅，也不编造赛况。

## 免费赛事数据接入状态

截至 2026-10-12，GRID 的 `/open-access/` 与 `/get-access/` 实际访问均跳转到商业方案页面；搜索引擎仍可能显示旧的免费申请内容。不能据此保证新账号可获免费实时权限。

其 [Open Access Quick Start](https://grid.helpjuice.com/client-help/open-access-quickstart) 仍列出两条接口：

- `https://api-op.grid.gg/central-data/graphql`：查询赛事、队伍及赛程。
- `https://api-op.grid.gg/live-data-feed/series-state/graphql`：查询比赛状态快照。文档提到进行中的比赛可返回实时快照，但实际覆盖、授权及调用额度须以获批账号为准。

该文档明确排除 Series Events、File Download 和 Stats Feed 等能力。接口名称包含 `live` 不代表任何账号可以访问，比赛快照也不等于完整逐事件数据。

申请前应向 [GRID 官方联系入口](https://grid.gg/plans/) 确认免费社区计划是否仍开放，以及本站展示许可、比赛覆盖、允许字段、刷新频率、署名和转播延迟要求。只有历史数据的账号不能作为实时数据源；无需为了启用观赛购买商业套餐。

取得官方回复和密钥后，接入步骤为：

1. 确认获批许可允许网站展示，并核对实际接口 schema 和目标比赛覆盖。
2. 在后端配置数据源密钥，选择比赛；密钥不得传到浏览器或提交仓库。
3. 将获准读取的比赛快照转换成下文的赛况格式，再通过签名接口提交。缺少的指标保持未知，不能补成猜测数据。
4. 联调队伍、地图与比分含义、异常响应、限额、比赛结束和转播延迟后再启用自动展示。

当前 WebTS 尚未接通 GRID，未配置其密钥或后台采集任务。签名接口可用，管理员仍可使用手动赛况模式。申请成功与实际实时联调通过是两个独立步骤。

## 管理员配置

1. 登录管理员账号，点击右上角设置 → **联合观赛**。
2. 输入完整直播间 HTTPS 地址，点击 **读取公开标题、介绍与封面**。补全读取不到的字段；封面可上传裁剪。
3. 设置活动标题、简介。默认只向登录用户展示；需要公开时主动勾选允许访客观看。
4. 只有确认平台允许站外嵌入时，才开启官方播放器。仍提供官方链接作为访问失败时的备用入口。
5. 可选站点已配置的 TeamSpeak 服务器与频道 ID。频道 0 表示服务器默认频道。用户主动加入，服务器密码和频道密码沿用现有连接流程，权限完全由 TeamSpeak 判断。
6. CS2 可选择不展示、免费手动更新或签名接口。没有数据源时选择手动或关闭，接口方式不会自动产生数据。
7. 在「副舞台」添加第二赛场、解说台等，各自填写名称和直播间地址，并分别确认是否允许嵌入。一次只加载选中的舞台，切换不主动改变语音频道。舞台共用该活动的语音入口和赛况；没有各舞台独立比赛数据时不会伪造对应关系。
8. 输入当前管理员密码保存。配置热更新，无需重启服务。页面每 10 秒读取最新配置和赛况，后台页面不自动覆盖尚未保存的表单。

B站短号（例如 `live.bilibili.com/6`）会在读取或保存时转换成实际房间号，再传入官方播放器的 `cid`。平台拒绝校验或房间不存在时给出明确提示，不保存未经校验的新地址；已有配置不受失败请求影响。升级前保存的短号需要管理员重新读取或保存一次。总校验时间最多 20 秒，站点同时最多两个校验任务。实际播放仍受赛事嵌入、版权、登录、地区和浏览器限制，校验成功不等于平台允许站外播放。参数依据：[B站官方活动播放器文档](https://live.bilibili.com/p/html/bilibili-live-player/docs/player-activity.html)。

手动模式提供队名、比分、地图胜场、阵营、地图、回合和比赛状态的表单。高级 JSON 可以补充选手、经济、武器、地图记录、回合胜方及比赛事件。每次更新都标注“管理员手动更新”。

## 一起说话与手机操作

仅观看不会申请麦克风或连接 TeamSpeak。点击加入观赛语音频道后，使用自己的身份登录服务器。切换不同服务器会先确认，再打开现有连接表单；没有权限的频道不会被绕过。已在该服务器时使用正常频道切换和密码流程。

桌面提供影院布局，手机使用单列内容、紧凑顶栏与固定语音控制栏。用户可以一边观看一边发言；播放器获得键盘焦点后，按键发言需要重新让网页获得焦点，或使用底部的按住发言按钮。原生 TeamSpeak 用户直接留在相同频道即可。

各自播放会有平台延迟差异，本版不提供帧级同步，不宣称直播播放器已启动就一定正在播放。

加载受支持的官方播放器后，切换到语音空间、首页或选择其他频道时，播放器变为可拖动小窗，显示本场比分与地图。点击展开回到观赛，收起画面保留播放器，关闭小窗停止加载；这些操作不主动断开原有语音。整页刷新会停止播放，需重新点击加载。不能嵌入的平台仍使用官方页面，没有站内视频小窗。

小窗位置仅保留在当前页面，不写入账号或浏览器持久存储。窗口缩放、手机横竖屏和可视区域变化时会限制位置，避开顶栏、语音栏及手机导航；可视高度不足时仅保留控制条。也可用方向键移动、Shift 加快、Home 复位、Escape 关闭，并尊重系统减少动画设置。Twitch 保留官方最小画面尺寸，无法容纳时收起画面或使用官方链接。

退出或更换账号会销毁旧播放器。活动撤销、播放地址变化或访问验证失败时停止旧播放；播放期间继续检查活动权限，浏览器后台节流可能延后检查。第三方平台仍可能自行暂停或限制后台播放，需逐平台实测。本站不会取得第三方视频的控制权。

观赛页的频道聊天发送到当前已连接的 TeamSpeak 频道，沿用原有权限和传输加密边界。语音成员列表显示当前频道成员。它们不替代 WebTS 好友端到端私信。

## 整个赛事与本场赛况

“本场赛况”当前支持两支队伍的一场比赛。“赛事总览”计划展示整个 Major 等赛事的赛程、阶段积分、晋级与淘汰队伍及淘汰赛对阵图；当前界面明确标注尚未接入，接口尚未提供完整赛事结构。不能从单场比分或直播标题自动推断瑞士轮晋级、种子排名或全赛事结果。

完整赛事需要获准使用、覆盖对应赛事的赛程和阶段数据。取得权限并验证真实数据后，再扩展结构和接入；没有数据时不显示虚构的排名或晋级结果。小窗只展示正在观看的本场简要数据，避免挤占语音和聊天操作。

## CS2 数据接口

这是未来接入获准使用的数据源的标准入口，不是对 B站或虎牙赛事 API 的包装。

在后台选择签名接口并保存，输入管理员密码生成密钥。密钥只显示一次，使用部署密钥加密保存，不能管理账号、身份或 TeamSpeak。轮换后旧密钥和旧活动 ID 立即失效；密钥不要写进公开仓库、浏览器或 URL。

`POST /api/watch/feed`，正文 UTF-8 JSON，最大 64 KiB。四个请求头：

```text
X-WebTS-Timestamp: Unix 秒
X-WebTS-Sequence: 当前活动单调递增正整数，最大 9223372036854775807
X-WebTS-Event: 后台显示的当前活动 ID
X-WebTS-Signature: 小写十六进制 HMAC-SHA256
```

签名输入为 `timestamp + "\n" + sequence + "\n" + event_id + "\n" + 原始请求体字节`，密钥为后台生成字符串的 UTF-8 字节。服务器校验签名、±60 秒时间窗、活动及序号，不以 Cookie 授权此接口。成功返回 `{"accepted":序号}`，重复或乱序返回 409，签名无效返回 401。每个来源 IP 每分钟最多 120 次；遇 429 应遵守 Retry-After，避免反复提交。

配置保存在加密的单独记录中，不改现有账号、身份和站点配置。仅保存当前赛况到内存，不保存视频或比赛历史；重启后暂时显示等待数据，防重放序号单独持久化，数据生产方继续递增。更换直播、开关活动、切换数据模式或轮换密钥会产生新活动 ID 并清空旧赛况。取得新 ID 后，数据生产方重新计数即可。

示例数据仅用于解释字段，不能作为真实比赛发布：

```json
{
  "tournament": "示例赛事", "stage": "决赛", "status": "live", "best_of": 3,
  "teams": [
    {"id":"a","name":"队伍 A","score":8,"maps_won":1,"side":"CT"},
    {"id":"b","name":"队伍 B","score":6,"maps_won":0,"side":"T"}
  ],
  "map":"de_mirage", "round":15, "phase":"进行中", "bomb":null,
  "players":[
    {"name":"选手","team":"a","kills":12,"deaths":8,"assists":3,
     "adr":85.4,"health":100,"armor":100,"money":3200,"weapon":"M4A1-S"}
  ],
  "maps":[{"name":"de_dust2","scores":[13,10]}],
  "rounds":["a","b","a"], "events":["第 3 回合队伍 A 获胜"]
}
```

状态仅支持 `scheduled/live/finished`，BO 支持 1/3/5/7；未知可选指标填 null。队伍必须恰好两支且 ID 不重复；选手最多 24 人、地图最多 7 张、回合记录最多 100 个、事件最多 50 个。正文仅允许规定字段，文字按纯文本显示。网页每 10 秒刷新，接口数据超过 30 秒未更新时标记过期，不将旧数据当作当前赛况。

## 安全与隐私

- 用户点击加载播放器后，第三方平台会获得 IP、浏览器信息以及该平台现有登录状态。YouTube/Twitch 等识别嵌入来源可能收到本站来源域名；不会把本站密码、邮件、设备密钥或身份私钥传给播放器。
- 页面默认不加载第三方播放器。封面在管理员读取时经后端限量下载、解码与重新编码后保存；访客不直接加载外部封面 URL。
- 公开网页及封面读取只接受公网地址，校验 DNS 所有候选地址、固定解析结果并逐次校验跳转；禁止凭据 URL、私网、非默认端口、HTTPS 降级和无界响应。并发读取最多两项，不使用站点 Cookie。
- CSP 仅增加三个固定官方播放器主机；仍禁止任意脚本、对象、外部连接以及本站被嵌套。管理员正文为纯文本，不接受任意播放器 HTML、脚本或插件。
- 网页赛况的来源取决于站长接入数据的准确性及授权；签名只能保证该请求来自持有密钥的数据生产方，不能证明比赛数据真实。
- 直播平台与 TeamSpeak 语音分别处理各自的数据。原有语音传输加密边界保持不变，联合观赛不将 TS 语音变成端到端加密。

站长应在自定义站点隐私政策中补充具体使用的直播平台、来源域名披露和可选公开活动范围；不应承诺第三方平台从不收集信息。默认关闭活动可避免在配置前引入第三方播放。

官方参考：[B站活动播放器](https://live.bilibili.com/p/html/bilibili-live-player/docs/player-activity.html)、[虎牙 SDK 能力](https://dev.huya.com/docs/miniapp/dev/sdk/)、[Twitch 官方嵌入](https://dev.twitch.tv/docs/embed/video-and-clips/)、[YouTube 播放器参数](https://developers.google.com/youtube/player_parameters)。第三方平台可随时调整站外播放规则，站长应在启用前核对。
