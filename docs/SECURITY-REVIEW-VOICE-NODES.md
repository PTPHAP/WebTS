## 本批安全边界

- TS机器HTTP只绑定回环，主动连主站已认证WSS；媒体保留DTLS-SRTP UDP直达，用户可见语音IP。不承诺隐藏源站、DDoS防护或语音端到端加密。
- 主站仅接受预先静态绑定的节点，每节点独立密钥。外层及内层HMAC均验证时间/nonce/路径/节点ID，拒绝Origin/Cookie，不开放CORS，不信任客户端自选TS目标。
- 配对须普通个人会话的管理员重验密码；码256位、服务端仅存摘要、最多5分钟、一次领取，新码废旧码。领取重新验证管理员、邮箱、封禁、公共设备与会话期限。已领取密钥按部署信任管理，退出管理员并不撤销节点，必须明确轮换。
- 桥接目的地只能是节点自身配置的回环控制地址；TS及图片文件端口固定。没有公网任意代理、没有复制用户库或站点主密钥。连接身份和声音仍进入节点内存，可信宿主机/运营者是必要前提。
- 每节点2备用通道/2握手预算，整体及节点任务受配置上限约束，帧16KiB、缓冲32KiB、发送与心跳有界，重连退避；取消关闭两端资源，不无限排队。
- 向导用标准输入传码，TLS正常验证且无跳转，限制响应大小并校验主站/节点ID；停机及写权限检查在领取前。更新既有配置/密钥保留ACL，失败尝试恢复。跨文件掉电事务不是原子操作，须安全备份与恢复核对。

## 本批发现和修正

1. 短响应通道直接释放TCP时，可能在未完成关闭握手的情况下丢掉最后响应，表现为内层WS握手未完成。针对性用例先失败；补有界关闭帧交换后原用例连续20次通过，正式回归再覆盖16次双通道并发ICE和连接撤销。临时诊断标签已删除，失败日志保留。
2. 多个等待者与备用通道到达竞争时，Notify的单一存储通知可能合并。等待者先注册再检查队列，避免已有备用通道却继续等待。
3. 临时文件替换配置可能丢失专用Windows运行账号的显式ACL。改为停止节点后更新既有文件，并保留失败恢复；密钥与配置均不通过放开权限解决。
4. 管理页轮询增加进行中保护和卸载取消，不叠加慢请求；密码完成后清空，配对码仅在组件内存、默认遮盖、到期清除，不写浏览器存储。
5. 新测试模板相对路径首次编译失败，已修正；浏览器首次因未设置项目已有浏览器目录而不能启动，设置本地目录后重新执行通过。保留失败记录，不将环境失败冒充产品测试通过。
6. 请求层面的中断恢复检查通过后，后台日志仍发现重复关闭的panic：futures的SinkMapErr只消费一次错误映射器，再次出错会panic。改为逐次映射的薄适配器；新增关闭后连续操作回归，原实现明确失败。原优化包因此阻断交付并保留拒绝记录，运行包检查增加后台panic扫描；不是把请求返回正常当作任务无异常。该问题影响通道任务稳定性，没有据此确认整个进程退出或权限泄露。

| 资源受限 | 连接/UDP分配上限、信令帧和队列、写入与握手超时、45秒存活检测、图像CPU/内存限制沿用。握手早期消息最多16条、每条8KiB，不无限缓存 |
| 节点无网站管理面 | 仅开放health、机器connect、机器rtc；无注册、账号、身份、后台和静态目录路由。ICE响应no-store |
| 不复制身份库 | 节点复用工作池运行时但只创建内存SQLite，不将连接身份写入；真实CLI隔离检查未生成数据库文件 |

## 本轮发现并处理

- 握手期间旧网关不读取网页关闭消息，可能保留身份至握手超时。现持续读取关闭，并对早期命令有界缓冲；节点和主站串联关闭检查通过。
- 新的回环接入会使原有“固定TS主机、服端选择文件端口”规则触及本机其他端口。节点额外绑定管理员指定的文件TCP端口，忽略TS文件通知中的其他IP/端口，不改变普通公网客户端行为。
- 新节点ICE请求初版遗漏项目显式rustls provider初始化，在隔离全链路中产生panic；已按现有网络模块方式配置ring provider，复测通过。
- 为避免异常节点事件导致JSON值赋字段时panic，节点返回必须是带有限长度type的JSON对象，二进制中转被拒绝。
- 初次测试夹具错误地把身份ID字符串作为结构体使用，已修正。严格Clippy发现宏中相邻if格式问题，修复后通过。旧失败日志保留，不把首次失败描述为首次通过。
- 全工作区格式化曾触及vendor；已恢复本轮产生的无关格式变更，用原上游archive＋公开补丁重建核对83个Rust/TOML文件一致，保留原有补丁，没有重置子模块。
- 频道图192KiB输出经Base64与JSON包装会超过原节点接收256KiB上限。仅将主站接收节点返回帧的上限调为1MiB，浏览器命令入站仍256KiB；真实本机WS检查完整图片消息通过、超过1MiB帧拒绝，不放开无限消息。
- Caddy初版模板中的无条件404可能按默认指令排序抢先响应。改为互斥handle路由，本机使用校验过官方发布摘要的Caddy 2.10.2检查模板适配/配置、health转发、认证ICE、WS101升级和未知路径404。测试只走HTTP回环，不等于公网TLS验收。[官方路由语义](https://caddyserver.com/docs/caddyfile/directives/handle)。
- Windows精简PATH测试发现启动器依赖PATH查找PowerShell，以及继承PowerShell 7模块路径可能阻断5.1安全模块加载。启动器改用系统绝对路径，显式加载当前PowerShell自带安全模块；新密钥设置ACL失败时清理本次刚创建的文件。修正后从解压包验证通过，失败记录保留。
