# 配置教程

[文档中心](README.md) · [安装教程](INSTALL.md) · [手动部署](DEPLOYMENT.md)

本文针对一条命令安装的 `/opt/webts` 实例。手动 Compose 或 systemd 部署的路径与服务名以自己的配置为准；不要混用两套管理命令。

## 先看命令要在哪里输入

普通使用者打开网页即可。下面是管理员维护时使用的命令；Linux示例在对应机器的root终端执行。

| 要做什么 | 在哪台机器输入 | 命令 | 执行后看哪里 |
| --- | --- | --- | --- |
| 打开网站管理菜单 | 运行WebTS网站的服务器 | `webts` | 终端显示中文菜单 |
| 查看网站容器状态 | 网站服务器 | `webts status` | 显示本网站的容器状态 |
| 查看网站错误 | 网站服务器 | `webts logs` | 显示本网站的近期日志 |
| 重新配置语音节点 | 运行TS和节点的Linux服务器 | `webts-node install` | 打开中文向导，已有值可以回车保留 |
| 启动已安装的节点 | TS节点Linux服务器 | `systemctl start webts-node` | 再用下一行查看运行状态 |
| 查看节点是否运行 | TS节点Linux服务器 | `systemctl status webts-node --no-pager` | `active (running)`表示程序运行；还需到网站后台确认“在线” |

`webts-node: command not found`不代表需要重装系统。若先前向导在配对阶段中断，程序可能已复制、快捷命令尚未创建；默认安装目录可用`python3 /opt/webts-node/scripts/node-linux.py install`继续。若连此文件也不存在，重新使用[节点安装教程](NODE-INSTALL.md)的下载入口。若提示`Unit webts-node.service could not be found`，则服务注册尚未完成。

Windows节点重新配置请双击原包的“开始安装.cmd”；更新使用原目录的`webts-node.cmd update`，检查配置使用`webts-node.cmd check`。Windows入口没有`status`子命令，运行连接状态在网站后台查看。

## 1. 网站地址和证书

准备一个域名，例如 `voice.example.com`，将 A 记录解析到服务器公网 IPv4。若配置 AAAA，IPv6 也必须实际提供这个网站和正确证书。证书警告应排查解析、代理与证书，不能靠跳过验证解决。

```bash
webts config
```

按中文提示填写域名、公网 IPv4 和本机端口：

| 项目 | 示例 | 用途 |
| --- | --- | --- |
| 域名 | `voice.example.com` | 浏览器 HTTPS 地址与同源校验 |
| 公网 IPv4 | 服务器实际公网 IP | 浏览器 WebRTC UDP 候选 |
| 本机端口 | `8080` | 回环 HTTP 网关端口，由代理转发 |

自动 HTTPS 模式由本实例 Caddy 申请证书，需要 DNS、TCP 80/443 可达。安装时选择已有代理模式，则在已有代理中添加独立域名规则，转发到 `127.0.0.1:8080`（替换成实际端口），支持 WebSocket，保留 Origin，并覆盖 X-Real-IP。示例：

```caddyfile
voice.example.com {
    reverse_proxy 127.0.0.1:8080 {
        header_up X-Real-IP {remote_host}
    }
}
```

已有代理如何加载配置由它的管理方式决定；先校验配置，不覆盖其他站点规则。若切换自动 HTTPS / 已有代理模式，按自己的 Compose 与代理配置维护，`webts config` 只调整域名、IP、监听端口。

## 2. 邮箱发信

```bash
webts smtp
```

| 输入项 | 示例或要求 |
| --- | --- |
| SMTP 主机 | 服务商提供的主机，例如 `smtp.qq.com` |
| TLS 端口 | `465` 为隐式 TLS；其他端口使用 STARTTLS |
| 登录邮箱 | 完整邮箱，例如 `mailer@example.com` |
| 发件邮箱 | 该账号获准发送的地址 |
| 授权码/密码 | 服务商生成的 SMTP 授权码，隐藏输入 |

授权码不能放入仓库、命令参数、Issue 或聊天记录。留空只在主机及登录账号未变时保留旧值；更换邮件服务须填写新授权码。启动显示“SMTP 已配置”仅代表可用配置，**不代表投递成功**。

实际验证：用自己的邮箱注册 → 检查收件箱/垃圾箱 → 打开验证链接 → 登录。验证和找回链接 15 分钟有效、单次使用。发信被拒绝时先检查授权码、发件人权限、云服务 SMTP 出站限制；自有发件域名按邮件服务文档配置 SPF/DKIM/DMARC。

## 3. 开通站长与进入后台

1. 通过网页注册站长邮箱，并完成邮件验证。
2. 在服务器执行 `webts admin`，输入这个已验证邮箱。
3. 重新登录网页，点击顶部 **站点管理**。

网站后台可设置 SMTP、服务器列表、默认服务器和自定义连接开关；保存需重新输入当前管理员密码。普通注册不会成为站长，站长也不会自动获得 TS 踢人、频道管理等权限。

## 4. 默认 TS 和自定义连接

```bash
webts server
```

填写目标公网地址，例如 `ts.example.com:9987`。可开启或关闭已登录用户填写自定义公网地址；初始默认关闭，连接仍需通过身份归属、目标地址、重复连接和加密检查。私网、回环和不安全目标被拒绝。

网页 **站点管理 → 服务器列表** 可维护多个服务器和默认项。名称用于网页展示，地址为目标 UDP 地址；每个物理目标使用一个配置 ID，避免地址别名造成重复连接。服务器或密码变更后重新连接；TS 服务器密码在连接窗口填写，不写入公开配置示例。

目标 TS 需开启 **Globally on** 全局语音加密，频道使用 Opus。网站以用户选定的真实身份连接；权限不足时在 TS 侧给该 UID 正确权限，不能用网站管理员角色绕过。

### 让某台TS服务器使用指定节点

在网页进入 **站点管理 → 基础配置**：

1. 在“服务器与连接”添加要连接的TS服务器，并先保存。
2. 在同页上方的 **“服务器走哪条路线”** 中找到这条服务器。目前路线选择在这个独立区域，不在名称和地址输入框里面。
3. 将“语音连接路线”选为 **“同机节点 · 语音直达TS机器”**，核对节点标识，验证管理员密码并点击 **“保存路线”**。选择“主站网关转发”则继续由网站服务器转发。
4. 首次配对按[节点教程](NODE-INSTALL.md)生成码并运行向导；已经配对的核对标识及“在线”状态即可。不同TS机器分别使用不同的节点标识。
5. 在语音空间选择**这条已保存的服务器**，重新连接。当前“自定义公网地址”走主站网关，不套用上述节点绑定。

确认是否生效：后台的“在线”表示节点已接上主站；连接后底部显示“同机节点直连”，语音设置里的“语音诊断 → 语音处理位置”显示“同机节点”，才说明本次连接选择了节点。浏览器链路若显示“TURN中继”，媒体仍经TURN，具体位置由站点的TURN配置决定。

若后台只有服务器名称、地址，看不到路线区域，先保存未保存的修改，按 **Ctrl＋F5**重新加载并打开后台；手机可重新加载页面。仍未出现时，需要核对当前网页版本或加载错误，不能靠在节点机器重复安装解决。

## 5. 热加载和重启的区别

| 修改位置 | 设置 | 生效方式 |
| --- | --- | --- |
| 网页站点管理 | SMTP、服务器列表/默认项、自定义连接策略、图片与头像限制 | 保存后热加载，无需重启 |
| `webts smtp` / `webts server` | 本地修改同一份加密后台设置 | 备份后短暂重启本实例，现有语音会断开 |
| `webts config` | 域名、公网 IP、本机监听端口 | 修改本实例配置并重启 |
| 手动配置文件 | RTC 端口、TURN、可信代理、容量等 | 备份、验证后重启自己的服务 |

后台 SMTP 和服务器设置优先于初始 TOML：**仅修改 TOML 不会覆盖已经保存的后台设置**。网页关闭自定义连接、删除服务器或修改目标地址会撤销受影响的活动连接，其他权限仍由 TS 决定。

## 6. UDP、防火墙和 TURN

| 连接方向 | 端口 | 用途 |
| --- | --- | --- |
| 浏览器 → 网站 | TCP 443，自动证书还需 TCP 80 | HTTPS/WSS |
| 浏览器 → 网关 | UDP 40000–40100，或自己的完整 RTC 范围 | WebRTC 加密语音 |
| 网关 → TS | 目标 TS 的 UDP 端口，常见 9987 | 原生语音/信令 |
| 网关 → TS 文件服务 | 实际文件端口，TS3 常见 TCP 30033 | 经典服务器头像 |
| 网关 → 邮件服务 | 配置的 TLS SMTP 端口 | 注册与找回 |

云安全组、主机防火墙与 NAT 映射都需一致。安装器不修改现有防火墙。HTTPS 能打开不代表媒体 UDP 一定可达。

受限网络可配置**带认证的公网 TURN**。编辑 `/opt/webts/config.local.toml`，在既有 `[rtc]` 下添加，不要重复创建表：

```toml
turn_url = "turns:turn.example.com:5349?transport=tcp"
turn_secret_file = "/app/secrets/turn-secret"
```

在主机 `/opt/webts/secrets/turn-secret` 保存与 TURN 服务一致的共享密钥，让容器 UID 10001 可读、文件权限 `0600`，然后 `webts restart`。文件内容不包含引号或注释。手动非容器部署使用相应主机路径。完整网络要求与长连接凭据边界见 [部署指南](DEPLOYMENT.md) 和 [支持范围](SUPPORT.md)。

## 7. 常用维护

站点后台还提供账号查询、详情、临时/永久封禁、解封、强制退出和管理员角色管理，所有修改复核当前管理员密码。具体操作与 AFK 使用见 [账号管理与 AFK](ACCOUNT-ADMIN.md)。

```bash
webts status
webts logs
webts backup
webts update
```

升级会先构建候选、备份再切换；新程序启动后可能已迁移数据库或写入新权限状态，因此就绪检查失败时停止本实例并保留新程序、当前数据和原镜像，不自动降级。备份目录的`update.json`记录前后源码位置与回退镜像名，不含凭据。优先向前修复；经兼容性核对才能在维护流程中回退，不能用旧数据库覆盖新数据。备份目录访问受限，仍需把数据库与密钥分别存到受控的加密离机位置。恢复必须使用**原密钥**，详细操作见 [备份恢复](DEPLOYMENT.md)。

公开站点前补齐 [隐私政策](../PRIVACY.md) 中的运营者联系方式、日志/备份期限、服务提供方与部署地域。测试实际验证邮件、语音、身份导出和权限拒绝后，再向社区开放。


## 8. 图片加载与头像限制

进入 **站点管理 → 基础配置 → 图片与头像**，修改数值，输入当前管理员密码，点击 **保存并立即生效**。默认值保持升级前行为；老配置自动使用默认值，不需要手工修改数据库。可一键恢复图片默认限制，再保存。

| 设置 | 默认 | 允许范围 |
| --- | --- | --- |
| 频道图片原文件（KiB） | 2048 | 64–8192 |
| 频道图片解码边长（px） | 2048 | 128–4096 |
| 频道图片压缩后（KiB） | 192 | 16–192 |
| 每篇介绍加载图片数 | 8 | 1–32 |
| 每连接网页缓存图片数 | 32 | 1–128 |
| 每连接每10秒频道图片读取数 | 8 | 1–32 |
| TS成员头像原文件（KiB） | 128 | 16–512 |
| 保存和上传头像（KiB） | 64 | 8–128 |
| 上传头像解码边长（px） | 512 | 96–1024 |
| 本地裁剪前头像原文件（MiB） | 2 | 1–8 |

1KiB = 1024字节，1MiB = 1024KiB。裁剪原图在浏览器本地处理，服务器接收裁剪、压缩后的头像；频道图片最长显示1280px，头像最长256px，设置更小的头像解码尺寸也会缩小裁剪输出。图片过于复杂时可能无法压到指定体积，应缩小裁剪范围或换图。目标TS的头像体积与文件权限规则仍会执行，站点调大不能覆盖TS限制。

保存无需重启、不会断开语音。新传输使用新限制；在途传输按开始时配置完成。已连接网页在约2秒内收到限制更新并清空频道图片缓存，按新数量重新读取；达到读取频率或全局预算时显示原因，可重试。已保存账号头像不会被自动删除，新保存和同步重新校验。

设置不能关闭类型/权限/路径/重编码检查，不能设为无限制。每连接图片传输并发仍为2；全局频道图片输入缓冲预算固定128MiB，最多2个图片/密码后台计算任务；频道图解码分配上限80MiB、头像16MiB。外部HTTP/HTTPS图片仍仅明确链接，不能用这里的数值开启外部自动请求；首页与公告图片沿用原独立限制。

## 好友私信存储

后台“加密临时存储”独立页面配置私有S3兼容桶、Region和受限Access/Secret Key，默认7天，支持1–30天与热加载。未配置不允许发送私信。请先关闭公共访问并配置生命周期；[完整配置与加密边界](FRIENDS.md)。基础配置/邮箱保存会保留此项。

接收原生 TS 头像时，原图解码采用独立的硬上限：最长边4096px、800万像素和32MiB预算，缩小后仍遵守保存体积限制；不绕过“TS成员头像原文件”限制。上传头像继续遵守后台设置的解码边长。
