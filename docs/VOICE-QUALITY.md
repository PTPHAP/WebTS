# 语音质量与异常恢复

在“语音设备设置 → 语音诊断”查看以下数据。未得到有效统计时显示“—”，不使用猜测值补齐。

| 指标 | 含义与范围 |
| --- | --- |
| 当前网页构建 | 本页实际加载的入口文件标识，用于双方核对是否为同一修订；不是服务器最新版本，也不是安全认证 |
| 音频上下文、实际处理方案 | 当前播放/处理上下文和正在运行的处理链；暂停、系统中断、处理失败与未启动分别显示，不把配置选择当作实际运行 |
| 接收轨道 / 输出元素 / 已暂停输出 | 当前接收链的数量快照；不含静音解码辅助附件，不等于频道人数或可听声音数量。已暂停输出与主动静音不同，刚连入时为零可以正常 |
| 回声消除 · 请求 / 设备报告 | 是否请求开启，以及采集设备实际报告的开关；未报告不推断为已关闭，报告开启也不代表实际声学效果通过 |
| 浏览器 ↔ 网关 RTT | 当前选中 WebRTC 候选链路的往返时间；直连与 TURN 分别显示 |
| 网关 ↔ TeamSpeak RTT | TS协议确认包／保活包的平滑往返时间，独立于浏览器链路；1.1.2起从实际发送计时，不包含发送前的本地排队 |
| 近期接收丢包、播放缓冲 | 相同音频流计数器的增量，窗口最多10秒；新连接、流计数重置和长时间恢复前台后重新采样 |
| 音频补偿采样与事件 | 浏览器为丢失或迟到音频合成的采样和连续补偿事件；不直接等同可听断音，也不据此修改麦克风处理 |
| 网关转发队列 | 该连接最近一个网关统计周期的入队等待时间，平均值及10ms分桶的P95上界；仅计算进入队列后的等待，不包含网络、AI或满队列的入队前丢弃 |
| 累计缓冲与丢包 | 当前浏览器连接的累计数据；网络恢复后仍可能保留旧影响 |

网关统计通常每2秒发布，实际窗口显示在界面；任务被阻塞时窗口可能更长。浏览器一次只保留一个未完成统计请求，3秒超时后清除旧数据显示不可用，迟到结果不再发布。统计失败不会中断通话，也不会无限追加未完成请求。

RTT、AI算法延时、音频设备、编码和播放缓冲属于不同环节，不能把这些数值简单相加当作完整说话到听见的延时。AI模型加载耗时也不等同运行延时。实际人声开口、音色、游戏负载及端到端P95需要另外进行同步声学测量。音频补偿字段依据 [W3C WebRTC Statistics](https://www.w3.org/TR/webrtc-stats/)。

1.1.2移除了默认GTCRN增强链中RNNoise识别专用段的重复PCM帧缓冲，逐采样对照测得此段从512采样延迟变为同一音频块输出，48kHz下减少约10.7ms。GTCRN模型、识别概率与Opus编码未更换，打字消音和严格人声模式保留。此结果是该处理段的时序验证，不等于整条语音链路的嘴到耳实测；严格人声模式和RNNoise单独降噪仍保留其必要的处理缓冲。

## 网络和设备故障

### 本地降噪的控制与回退（1.1.3 候选）

固定版本的 RNNoise/GTCRN worklet 使用消息监听器接收控制，需要显式启动其 MessagePort 队列。候选修复使识别专用模式、打字消音和销毁消息实际生效，避免增强降噪之后意外再次执行 RNNoise 过滤。同一 AudioContext、同一合成人声输入的对照中，处理段信号延迟由约 52.5ms 降为 31.9ms；该数值仅对应本地处理段，不是完整语音嘴到耳延迟。

增强模型故障时，输出先静音，确认 RNNoise 已恢复过滤后才继续发送；确认超时则暂停麦克风处理。模式切换同时清空识别直通模式的旧音频缓冲，避免回退后重放未过滤的残留样本。额外打字压音最多衰减约 6dB，保护弱起音；AI 噪声模型继续工作。初始化、热切换和故障回退均保留频道与收听，不以发送原始麦克风作为静默回退。

回归同时使用真实 WASM、按 MessagePort 启动规则派发消息的单元夹具和实际浏览器音频节点；浏览器故障检查注入处理器错误回调，核对真实跨线程确认和恢复后的输出。Windows 测试环境没有 AudioContext 的 WebKit 项明确跳过，不能当作真实 Safari 或手机音频通过。

### 停顿后越来越慢（1.1.3 候选）

TeamSpeak 的结束发言包不包含可播放的 Opus。网关将它转换到浏览器 RTP 时，需要保留下一段语音前的真实停顿，并给第一包设置新语音段标记；不能仅靠递增包序号把停顿压成 20ms。旧实现对短于 200ms 的停顿存在这个问题，浏览器会把时间轴不匹配吸收到接收缓冲中。采样时钟依据 [RFC 7587 §4.1](https://www.rfc-editor.org/rfc/rfc7587.html#section-4.1)，语音段标记采用 [RFC 3551 §4.1](https://www.rfc-editor.org/rfc/rfc3551.html#section-4.1) 的建议。

本轮在本机以实际 Rust Media、DTLS-SRTP、Opus 和 Edge 播放链运行合成对照：300ms 发送、120ms 停顿，旧实现 8 秒内累计缓冲约 241ms，后半段播放落后约 440ms；修正后 30 秒的采样窗口约 74～92ms，缓冲约 25ms，网络丢包均为零。停顿本身仍会产生浏览器静音补偿，不能把补偿采样全部解释为网络丢包。上述数值是该隔离回环的信号相关测量，不是生产环境或完整嘴到耳 P95。

修正在网关／节点程序内，既保留 Opus 原样转封装与加密要求，也保留连续音频的采样时钟。使用“同机节点直连”时应更新对应 TS 机器上的节点，而非只刷新网页。测试 `media::tests::speech_` 覆盖短停顿、不同帧时长、乱序与重复、序号和时间戳回绕及加密状态拒绝。

候选版将合法的短距离乱序包交给浏览器现有抖动缓冲恢复：网关只保存固定大小的接收位图，不增加排队等待；重复、过旧、跨发言段或无法可靠推算时长的包仍拒绝。长静音后的采样换算使用整数模回绕，避免超过一个RTP时间戳周期后饱和。保留连续无包超过200ms时的时钟重同步保护，避免UDP发言结束标记丢失后永久失去恢复机会；到包时间本身不能唯一还原发送时刻，长网络停顿后的实际恢复仍须验收。

隔离的双参与者 Edge／Rust Media 回环中，每50包交换一对相邻包且不删除数据，旧实现产生17个丢包；修正后同类检查为0丢包，并覆盖序号跨65535回绕，协商仍为AES-256-GCM。这是该转发缺陷的回归证据，不代表所有实际音乐卡顿已解决。长网络停顿后的缓冲恢复、发送端首字预留及与原生客户端的四方向对照仍是发布验收项。

### AI故障回退（开发补充，尚未随正式安装包发布）

键盘增强处理器停止时，输出先静音，待RNNoise工作线程确认恢复过滤后再继续播放。切换会清除识别直通模式残留的PCM缓冲；确认超时则维持静音并报告处理失败，频道与收听的保持逻辑不变。输出节点在回退前后保持稳定，重复故障通知和销毁不会留下额外恢复计时器。此保护不会关闭回声消除或降低传输加密。

### 移动端外放回声（开发补充，尚未随正式安装包发布）

回声消除由麦克风采集端的浏览器/系统提供，本地 AI 降噪不能替代它。语音诊断分别检查请求开启与设备实际报告；“设备未报告”不代表已经关闭，“已启用”也不保证任何音量或房间都能消除回声。

开发版脱敏报告格式为 `webts-diagnostic-v4`：保留原有字段，增加 `frontendBundle` 与 `runtime`。构建只接受本页同源、无查询参数的标准入口路径；未知构建为 `null`。运行状态使用固定枚举，数量只接受非负安全整数，未知数据为 `null`。不导出原始设备设置、轨道编号、账号、地址、设备名称、密钥、聊天或录音；不自动上传、保存或新增诊断轮询。下载前请自行预览，再决定是否分享。正式旧包可能仍导出旧格式，排查时先核对加载构建。该标识用于排障，不用于验证代码真实性。

收听音量、成员音量及发言时回声减弱统一通过 Web Audio 增益节点控制，静音另有媒体元素静音保护。辅助解码附件只绑定独立的、已禁用的远端音轨副本，再加元素静音/零音量，原始音轨仅进入正常处理链；不再用“音量读回为零”作为不会重复播放的保证。这考虑了 [Apple 记录的 iOS 媒体音量限制](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/Using_HTML5_Audio_Video/Device-SpecificConsiderations/Device-SpecificConsiderations.html)。依据 [W3C 媒体流规范](https://www.w3.org/TR/mediacapture-streams/#dom-mediastreamtrack-enabled)，禁用音轨给消费者的是静音；副本在播放链销毁时停止，不改变借用的原始轨道。

真实本机 WebRTC 检查会故意将辅助元素取消静音、音量调满，确认副本采样仍为零、正常处理链有声，并覆盖双向收发、重新协商、收听静音与恢复。这是针对重复播放旁路的验证，不是对所有移动内核或实际手机声学效果的保证。浏览器差异仍需按实际平台验收；直接删除远端解码附件可能造成无声，不应作为未经验证的兼容修复。

重新协商可能再次通知同一远端音轨，接收端会复用现有播放链，避免叠音和旧播放器失去回收入口；音轨结束后释放播放链，后续新轨道正常建立。依据 [W3C 远端音轨处理流程](https://www.w3.org/TR/webrtc/#processing-remote-mediastreamtracks)，并通过本机真实 WebRTC 更改流关联后的重新协商验证。此项不能替代两部外放手机的声学验收。

两部手机复测时，双方都须加载同一修订版。先在不同房间以适中音量外放，依次单方说话、同时说话、静音/恢复、热切换降噪和切换页面；记录哪一方听见自己的回声及双方报告的回声状态。再比较一方戴耳机的情况。不要仅凭模拟 iPhone 的桌面浏览器结果宣称实机通过；同一房间多设备外放形成的交叉声路也需要单独区分。

WebRTC进入短暂断开状态后等待10秒，期间恢复则保留连接；持续断开或明确失败时回收旧连接，再按已有1–30秒退避自动重试。手动断开、会话失效及权限撤销仍停止相应操作。重连尝试恢复断线前的频道，目标不存在、身份变化或权限不足时不会绕过服务器限制，必要时提示输入频道密码。

麦克风暂停、采样失败和设备切换优先恢复采集链，保留服务器连接与收听；降噪热切换保留当前处理链，失败时不会静默降级为发送原始麦克风。浏览器休眠、系统网络变化和移动系统后台限制仍需要实机验证。

转发队列最多8包，并拒绝等待超过200ms的旧包；自由发言开口缓冲与转发使用同一到达时间，不额外延长旧包的保留期。负载满时可能产生音频缺口，这是避免积压旧声音的取舍，不降低加密下限。主动关闭明确撤销加密就绪状态、取消接收任务并关闭RTC传输。

## 隔离长时测试

设计参考：[TeamSpeak官方音频示例](https://business.teamspeak.com/features/client-audio-example/)分别提供人声检测、降噪、自动增益和回声消除控制。公开接口不等于客户端完整内部实现，也没有给出TS6全部算法和缓冲参数。WebTS默认AI链保持降噪输出与发言识别分工；识别专用段直接输出当前PCM，避免再次缓存。后续延迟对照分别测采集、处理、转发和播放，并以同设备、同服务器的实际声音比较为准。

开发环境安装固定Rust依赖后，可单独运行：

```sh
cargo test --package web-ts --test rtc_soak --locked -- --ignored --nocapture
```

默认持续30分钟，50组本机真实UDP/DTLS-SRTP连接、其中10组双向合成Opus静音。它只检查传输、套件、计数和关闭流程；不连接生产TeamSpeak，不替代真人听验、降噪处理、TS网关全链路或Linux参考机器容量验收。测试默认被常规快速测试跳过；可通过`WEBTS_SOAK_SECONDS`指定10–7200秒，短时结果不能作为30分钟验收。`WEBTS_SOAK_PAIRS`可指定1–200组连接，`WEBTS_SOAK_ACTIVE_PAIRS`指定其中同时传输的组数，不超过连接组数；每组包含两个对等端，双向传输。每个活跃组分别检查送达率，避免汇总数据掩盖单组异常。测试中的套件复查频率与实际网关保持一致，不随音频包逐帧获取统计。输出仅含数值摘要，原始音频和网络地址不写入报告。

例如扩大隔离负载到100组连接、32组双向音频（运行前确认本机资源充足）：

```bash
WEBTS_SOAK_PAIRS=100 WEBTS_SOAK_ACTIVE_PAIRS=32 cargo test --package web-ts --test rtc_soak --locked -- --ignored --nocapture
```

这些参数只改变测试负载，不修改站点连接上限。主站和节点的`max_connections`目前默认50、允许配置1–1000，配置的UDP端口数也必须足够；配置上限不等于已经验证的容量。10组语音是原始验收目标，不是产品限制只能10人同时发言。生产容量需要覆盖实际TeamSpeak权限连接、同频道多发言者到多浏览器的转发以及目标机器资源。

设置 `WEBTS_SOAK_SPEAKERS` 可运行多发言者转发模式：此时所有连接组均为听众，须令 `WEBTS_SOAK_ACTIVE_PAIRS` 等于 `WEBTS_SOAK_PAIRS`；连接组数最多 128，发言者数不超过连接组数。每个听众预分配与成员数量相同的音轨，实际传输指定数量的发言者；按每条 SSRC 核对送达率与接收间隔，避免汇总掩盖单轨丢失。例如 50 个听众、10 个发言者产生 500 条单向加密音轨，而非 10 对独立通话：

```bash
WEBTS_SOAK_PAIRS=50 WEBTS_SOAK_ACTIVE_PAIRS=50 WEBTS_SOAK_SPEAKERS=10 cargo test --package web-ts --test rtc_soak --locked -- --ignored --nocapture
```

此模式仍是本机 RTC 传输测试；接收观察器没有浏览器解码和播放开销，不包含 TeamSpeak 连接与权限处理。不能据此直接扩大生产容量。测试报告保存在忽略的 `.cache` 目录，不属于公开发布附件。

Windows不允许链接器覆盖运行中的测试程序；运行长时测试期间可执行其他检查，完整重编译应在长时测试结束后进行。
