# 好友、加密私信和临时对象存储

这是一项 **实验功能**，与原生 TeamSpeak 私聊分开。未配置对象存储时可以管理好友及私信身份，但不能发送私信，系统不会降级为明文。

## 用户操作

1. 登录后点右上角双人好友按钮；手机进入底部“好友”。无需连接 TS 或启用私信密钥就能复制好友码、发送和接受请求。需要聊天时选择“启用 / 解锁私信”。
2. 默认只需输入网站密码确认，设备自动生成私信身份和不可导出的AES-256设备保护密钥，同一浏览器再次打开好友时自动解锁。无需另外配置私信密钥或口令。共享设备可在首次启用或导入口令备份时取消自动模式，使用独立的16–256字符私信口令。
3. 复制自己的好友码，或输入对方的24位好友码。双方启用私信后，在当面或另一个可信渠道逐组核对安全码，完全一致才勾选信任。
4. 双方先解锁设备，才能取得对方的一次性密钥并发送。对方随后关闭页面仍可接收临时密文，但需要回到原设备解锁查看。
5. 可发送文字、内置表情贴纸，以及经过裁剪和JPEG归一化的图片。图片与正文使用相同加密路径，外部图片不会自动加载。表情选择面板显示当前会话的实际保护方式；矮窗口中可滚动，不将服务器可解密模式标为E2EE。
6. 发送失败时，待发箱保存同一消息编号及密文，重试不会重新加密或生成重复消息。对方已换设备时可放弃待发密文，再发送新消息；放弃不能撤回服务器可能已经收到的消息。

**一次一台设备、一个标签页处理私信。** 同浏览器使用 Web Locks 防止并发改写棘轮；其他设备接管要复核网站密码，旧设备的私信请求立即失效。当前不支持多设备消息分发或历史同步。网站语音及 TS 聊天不受此限制。

好友列表、请求和会话使用账号的社区昵称、头像及个人介绍，保存个人资料后自动刷新；未设置昵称时显示“WebTS用户 + 账号ID”，不向好友暴露登录邮箱。TS 连接中的临时昵称和服务器头像仍遵循独立的同步开关。

桌面面板可选择右侧 **悬浮** 或 **停靠**，偏好保存在当前浏览器；停靠会给工作区留出空间，电脑缩小窗口时保持所选方式及三栏顺序，过窄时可横向滚动；无悬停的触屏设备在760px及以下使用独立的好友列表与会话页面。切换显示方式或去首页保留同一个私信引擎及待发密文，不重新创建密钥。

好友请求、对方接受请求和新私信各自触发提示音与可打开好友的提醒；徽标包含未读私信和待处理请求。初次打开只显示已有徽标，不重复响旧通知。浏览器首次点击、系统静音和后台节流仍会影响声音，详见[通知设置](NOTIFICATIONS.md)。

“设备与备份”提供可选的口令加密身份导出，需复核网站密码并设置16–256字符备份口令；自动模式可另设备份口令，手动口令模式沿用原口令。文件可跨设备导入；导入前先验证口令和账号公钥，失败不会覆盖本机记录。成功导入并确认替换后，身份和旧状态在一个事务中替换/清除，下次解锁创建新私信设备；不保留本机旧会话状态。自动设备记录不能直接作为可移植备份。

身份备份只含加密的初始私信身份，不备份聊天历史或后来的一次性密钥。新设备导入原备份、输入备份口令及网站密码接管后，只能读取发给新设备的后续消息。清空浏览器而没有可用备份会丢失私信身份；网站密码找回无法恢复它，也不允许静默替换已登记公钥。不要在公开 Issue 上传备份。

## 使用了哪种加密

- 密钥交换、消息密钥轮换和双棘轮使用固定 **vodozemac 0.11.1 的标准 Olm v1**，编译成同源 Rust/WASM；不启用实验 Olm v2，也不启用 `fuzzing`。
- Olm v1自身使用AES-256-CBC及截断为8字节的HMAC-SHA256认证；额外的AES-256-GCM内容加密不把Olm认证强度升级成128/256位。不要把本功能宣传为Signal同等级实现或所有环节均为256位认证。语音链路的SRTP套件要求仍独立执行。
- **Olm 与 Signal 协议不同**。没有接入 Signal 服务、X3DH/PQXDH、多设备协议或完整 Matrix 网络；没有自行编写双棘轮算法。
- 账号公开身份包括 Curve25519 与 Ed25519 公钥。一次性公钥由身份签名，发送设备独立验签；安全码绑定双方完整公开身份。
- 每条文字/图片内容使用随机 AES-256-GCM 密钥和12字节随机 nonce；该密钥由 Olm 消息保护，认证上下文绑定站点、编号、双方和焚毁策略。重复、篡改、错设备、错身份及错上下文会拒绝解密。
- 浏览器私钥、棘轮状态及有限消息缓存存入 IndexedDB 前使用AES-256-GCM加密。默认保护密钥为WebCrypto生成的不可导出CryptoKey，通过浏览器结构化克隆持久保存；可选手动口令与可移植备份采用PBKDF2-SHA256（600000次）派生密钥。自动密钥和密文都在本机，不等同于硬件隔离或操作系统密码保险箱；同源JavaScript仍可使用密钥。锁定按钮释放当前页面状态，自动模式重新打开仍可解锁。普通与定时阅后即焚缓存合计最多60条且总量2MiB；到期缓存在下次保存时清理，浏览器磁盘和备份不承诺物理擦除。
- 网关只收到 E2EE 密文，再使用部署密钥 AES-256-GCM 包裹后写入私有桶。SQLite保存账号关系、时间、消息编号、摘要、已读/焚毁状态及对象索引，不保存正文或图片。

成熟的密码库不等于本项目接入已经经过独立密码审计。本功能仍需真实存储供应商、浏览器互操作和外部安全复核。

原生 **TS 频道/服务器聊天和 TS 私聊**继续使用 HTTPS/WSS及 TS 原生协议传输保护，网关能看到内容；不是好友E2EE，不能把原生 TS 客户端单方面升级为这种私信协议。

## 可选的服务器可解密模式

**每个新好友会话默认E2EE，内容始终使用AES-256-GCM。** 选择关闭E2EE时，在会话的“选择服务器可解密模式”中输入网站密码并明确确认；对方也需同意才能生效。只有一方同意时仍使用E2EE。每台发送设备还须保存绑定双方公开身份的本机同意记录，单靠服务器返回的模式不能使未同意设备降级。

此模式使用标准AES-256-GCM内容加密；消息密钥经HTTPS一并交给本站，本站能够解密文字和图片。网关再以部署密钥AES-256-GCM包裹消息及内容密钥后存入私有桶。它属于服务器可解密的传输/存储保护，**不是端到端加密**。HTTPS使用实际TLS协商套件，不承诺所有网络跳均为AES-256。

任一方可恢复E2EE。每次实际选择变化增加模式版本，旧版本或错误模式的发送被拒绝，正在上传的消息失效，避免切换后迟到消息重新送达。切换前先重试或放弃本机待发消息；已送达的历史消息保持原模式，不转换或解密旧E2EE消息。列表、会话和每条消息显示保护方式。E2EE发送仍需核对安全码，服务器可解密模式不提供同等身份和内容保密承诺。

## 临时存储与阅后即焚

默认保留7天，管理员可改为1–30天；新设置只影响之后的消息。到期后 API 立即拒绝读取，后台每10秒检查并尝试删除对象；桶故障时重试，桶生命周期必须作为兜底。

启用阅后即焚后，在发送区选择 **1分钟、10分钟、30分钟、1小时、12小时、24小时、2天、4天或7天**，默认1分钟。选择只影响后续发送的消息，不改变已发消息；接收方完成认证解密并成功保存棘轮状态后发送已读确认，服务器从首次确认开始倒计时，重复确认不延长。正文中的所选时长受加密认证保护，客户端会拒绝不匹配的路由参数。截止时间取已读计时和服务器原保留期限中的较早者；例如默认7天保存、发送6天后已读且选择7天，则仍在第7天到期。未读消息仍受默认期限限制。

新定时消息在本机有限AES-256-GCM加密缓存中保留未到期正文，以便刷新后继续查看，不再次消耗棘轮消息密钥；缓存容量上限可能提前淘汰旧消息。接收页面在成功解密时也建立本地上限，服务器确认和后续同步只能缩短此截止时间。到期API立即拒绝读取，页面停止展示，后台尝试删除密文对象。未带时长的旧版消息仍执行服务器确认后立即禁止读取、当前页最多60秒、正文不写入持久缓存的兼容规则。**无法阻止对方截图、另存、复制或恶意修改客户端，无法保证已存在备份、对象版本或副本即时物理删除。**

网站无法识别密文中的“敏感信息”，不会自动分类或承诺敏感内容从未入桶。不要发送不希望对方保存的内容。屏蔽/删除好友会使双方临时消息立即过期，随后尝试删除；不能擦除对方已经保存的副本。

## 管理员配置 S3

后台 → **加密临时存储**，独立页面填写：

| 项目 | 说明 |
| --- | --- |
| API端点 | 路径式 S3 兼容 HTTPS 公网端点，端口443；例如 `https://s3.us-east-1.amazonaws.com`。使用API端点，不填CDN/网站地址 |
| 桶、Region | 私有桶名及供应商的签名区域；雨云未提供Region时可留空使用兼容默认值，详见[雨云配置](OBJECT-STORAGE.md) |
| Access/Secret Key | 专用于此桶与 `webts-temporary/*` 前缀；保存后后台不回显，留空保留 |
| 保留天数 | 1–30，默认7；旧消息原期限不变 |
| 网站密码 | 当前管理员密码；保存后热加载，无需重启 |

关闭公共访问和公共 ACL。仅授予固定前缀 **GetObject、PutObject、DeleteObject**；不授予管理员、列举全部桶或读取其他项目权限。示例AWS IAM资源范围：`arn:aws:s3:::YOUR_BUCKET/webts-temporary/*`。不同供应商的权限语法需按其文档配置。

为 `webts-temporary/` 配置不长于保留天数的生命周期删除；清理非当前版本、复制目标、删除标记和已有备份，建议此临时桶不启用版本保留或对象锁。生命周期太短会使尚未到期消息提前无法读取。系统没有自动替你创建桶或修改云权限。

端点执行证书验证、公网 DNS 解析与固定地址，不跟随重定向，不使用系统代理，拒绝回环/内网/云元数据目标。上传和下载最多2个并发，单份密文上限384KiB，15秒HTTP超时和18秒总超时。最多10000个站点消息索引、每发送账号1000个、每分钟20条；每账号最多132个好友及请求、每分钟5个新请求。达到限制时拒绝新增。

关闭存储开关停止新发送；现有密文仍按原期限读取和清理。有消息或检测对象索引时禁止切换桶/端点，避免遗失旧对象；同桶修正Region和轮换凭据允许热加载。确保新的密钥仍有删除权限，否则删除会重试并阻止迁移。后台显示索引数量，提供加密测试文件的上传/读取/删除检测；[完整配置与排错](OBJECT-STORAGE.md)。一个实际雨云桶已完成小规模加密对象联调，完整跨浏览器私信验收仍在进行。

## 威胁边界

E2EE保护诚实客户端之间的消息内容，不隐藏好友关系、大小、时间、IP或已读状态。运营者依然控制网站提供的 JavaScript；若站点/发布链被入侵、设备存在恶意扩展、口令被窃取或对方主动保存内容，E2EE不能保证保密。请使用可信部署、核对安全码、保持设备安全，并复核构建来源。

## 从源码构建

安装脚本与 Docker 自动生成 WASM；生成的JS/WASM不提交源码仓库。手动构建：

```bash
# Linux x86_64，固定项目 Rust 工具链；需要 curl 和 sha256sum
sh scripts/prepare-vendor.sh
sh scripts/build-crypto.sh
cd web && npm ci && npm test && npm run build
```

Windows使用项目本地工具链及 `scripts/build-crypto.ps1`；先安装 wasm-bindgen 0.2.129，或通过 `WEBTS_WASM_BINDGEN` 指定其可执行文件。WASM按需加载，不在进入首页时初始化棘轮。

依据：[Olm/vodozemac](https://github.com/matrix-org/vodozemac)、[标准Olm说明](https://spec.matrix.org/latest/olm-megolm/olm/)、[Olm v2实验边界](https://matrix.org/blog/2026/02/analysis-of-reported-issues-in-vodozemac/)、[AWS生命周期](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lifecycle-mgmt.html)。

新私信设备从身份备份接管时，与该账号有关的旧临时消息立即过期并尝试删除，避免旧设备的迟到密文进入新会话；需要保留的内容请在切换前自行处理。重新解锁原设备不会清除旧消息。已解密副本不能撤回。

自动密钥依据：[W3C WebCrypto密钥存储与结构化克隆](https://www.w3.org/TR/2017/REC-WebCryptoAPI-20170126/#cryptokey-interface)。不可导出属性限制标准API导出，不表示网站脚本无法调用密钥。
