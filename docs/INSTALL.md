# 一条命令安装与中文管理

自动安装支持 **Debian 12、Ubuntu 24.04 的 Linux 服务器**。在服务器 SSH/控制台的 root 终端执行：

```bash
apt-get update && apt-get install -y curl ca-certificates && bash -c 'f=$(mktemp) && curl -fsSL https://raw.githubusercontent.com/PTPHAP/WebTS/main/install.sh -o "$f" && bash "$f"; r=$?; rm -f "$f"; exit "$r"'
```

安装器下载本仓库与固定协议子模块，通过 Docker 从源码构建。首次构建需要时间与网络；它不要求下载 Release 包，不创建演示账号，不内置邮箱、身份或密钥。HTTPS 下载失败时停止，不禁用证书验证。非 root 请先 `sudo -i`。

安装目录 `/opt/webts`，管理入口 `/usr/local/bin/webts`。若这些位置已有非本项目文件，安装会停止。不会安装或修改 TS 服务，不调整现有防火墙或覆盖其他网站代理。安装缺少的系统依赖时使用发行版签名软件源；已有 Docker 不会被重装。

缺少 Compose V2 时，按 [Docker 官方插件安装方式](https://docs.docker.com/compose/install/linux/) 下载固定 `v2.39.4`（x86_64/aarch64），核对官方 SHA-256 后安装插件，不为安装 Compose 而卸载或替换已有 Docker。已有有效插件继续使用。

## 首次填写

中文提示依次收集：

| 项目 | 填写内容 |
| --- | --- |
| 网站域名 | 例如 `voice.example.com`，提前将 A 记录指向本机公网 IP；不要填写协议或路径 |
| 公网 IPv4 | 网关实际可达的公网 IP，用于 WebRTC UDP 候选 |
| 本机端口 | 默认 `8080`，只监听回环地址；已占用时选择其他端口 |
| 默认 TS 地址 | 例如 `ts.example.com:9987`；只能使用获授权的公网目标 |
| 站长邮箱 | 后续通过网页注册并验证，之后授予管理权限 |
| HTTPS | 自动证书，或使用已有反向代理；80/443 已占用时自动保留已有代理 |
| SMTP | TLS 主机、端口、登录邮箱、发件邮箱、授权码 |

授权码使用隐藏输入，不放入命令历史、启动参数或 `setup.json`。部署密钥随机生成，已有数据库缺少原密钥时停止，不生成替代密钥。

使用自动 HTTPS 时，安装器启动本实例的 Caddy 自动申请证书。域名解析、TCP 80/443 必须正确，申请完成后用浏览器访问 `https://你的域名`。已有代理时，管理员需在现有代理中添加这个域名，转发到安装时选定的 `127.0.0.1:端口`，保留原始 Origin 并覆盖 X-Real-IP；安装器不会接管旧代理或重启其他网站。

云安全组与主机防火墙需放行 TCP 80/443 和 UDP **40000–40100**，并允许本机访问目标 TS 的语音 UDP 端口。若有 NAT，映射完整 UDP 范围。目标 TS 开启 **Globally on** 语音加密，频道采用 **Opus**。浏览器不直接连接 TS，TS 看到的是网关的出口 IP。

## 邮箱与站长账号

QQ 邮箱常用 `smtp.qq.com`、`465`，使用邮箱设置生成的 SMTP 授权码；其他服务按其 TLS SMTP 文档填写。465 使用隐式 TLS，其他端口使用 STARTTLS；不支持明文 SMTP，不跳过证书校验。发件邮箱需要该 SMTP 账号的发信授权。发到垃圾箱时，检查发件域名的 SPF/DKIM/DMARC 与邮箱服务的发件策略。

1. 在网站用站长邮箱注册，检查收件箱/垃圾箱并点击验证链接。
2. 在服务器运行 `webts admin`，填写该**已验证**邮箱。
3. 重新登录网页，点击顶部 **站点管理**。

普通注册不会自动获得管理员权限。管理员可以管理网站邮箱、默认 TS、服务器列表与自定义连接策略；保存需复核当前密码。网站管理员身份不增加任何 TeamSpeak 权限：频道、踢人、头像等操作仍由当前 TS 身份与目标服务器决定。

## 中文菜单与命令

输入 `webts` 打开中文菜单。也可以直接执行：

| 命令 | 功能 |
| --- | --- |
| `webts setup` | 首次引导，或保留已有配置后继续失败的构建/启动 |
| `webts config` | 域名、公网 IP、本机监听端口 |
| `webts smtp` | SMTP 邮箱与授权码；留空只在主机/账号未变时保留授权码 |
| `webts server` | 默认 TS 地址及是否允许已登录用户自定义公网连接 |
| `webts admin` | 授予已验证邮箱网站管理权限 |
| `webts start` / `stop` / `restart` | 启动、停止、重启本实例 |
| `webts status` / `logs` | 服务状态、最近日志 |
| `webts backup` | SQLite 一致性备份与配置/密钥备份 |
| `webts update` | 从仓库获取新源码、先构建，再备份切换；启动失败回退程序 |
| `webts help` | 查看命令 |

服务器上的命令需要 root/sudo，网站普通用户不能执行。CLI 的邮箱/TS 配置直接通过本地受控命令更新后端加密设置，保留其余列表与策略；不会出现“配置文件改了但被后台旧配置覆盖”。CLI 配置会短暂重启本实例并断开语音，失败则恢复配置。网页 **站点管理** 的邮箱/服务器设置仍支持热加载，无需重启。

`get-settings` / `set-settings` 是网关供本地管理器使用的内部命令，前者包含 SMTP 凭据，仅由管理器捕获到内存；不要手动重定向到公共日志或粘贴其输出。浏览器管理员接口仍不返回授权码。

## 文件与升级

`data` 保存 SQLite，`secrets/master.key` 是身份和后台配置的加密密钥，`secrets/smtp-password` 用于初始发信配置；后续后台设置加密保存在数据库。升级保留这些文件与账号、身份、UID；切勿手动替换部署密钥。

备份在 `/opt/webts/backups/日期时间`，包括一致性 SQLite 快照。安装目录与备份限制访问；仍应将数据库与密钥分别移到受控的加密备份位置。恢复前停止网关，恢复数据库和**原密钥**及对应配置，检查文件权限后启动，验证独立账号 UID 与通话。不要只恢复数据库，也不要把备份上传到仓库。

自动更新只切换 WebTS 自己的程序与容器，不运行 `docker system prune`、不删其他容器，也不清理旧备份。出现错误先查看 `webts logs`；完整手动部署、TURN、备份恢复和配置说明见 [DEPLOYMENT.md](DEPLOYMENT.md)。手机语音、TS6、TURN 长连接及容量目标仍需独立验收。
